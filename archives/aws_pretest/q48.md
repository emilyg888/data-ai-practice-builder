Question
A large ecommerce company is developing a customer service AI-powered chat assistant by using Amazon Bedrock. The company needs the chat assistant to be able to support both simple product questions and more complex reasoning tasks. Simple product questions are 80% of the queries. Complex reasoning tasks are 20% of the queries. The solution must be cost-effective and require minimal operational overhead while maintaining response quality.

Which solution will meet these requirements?

Correct answer: B

A
Configure Amazon Bedrock with provisioned throughput for an Anthropic Claude Sonnet model to handle all queries. Implement response caching using Amazon ElastiCache (Redis OSS) to store frequent responses with 24-hour TTL. Use Amazon CloudWatch metrics to monitor cache hit rates and adjust provisioned capacity based on traffic patterns.

Incorrect. Provisioned throughput with Claude Sonnet provides consistent performance. However, this solution uses a high-capability model for all queries, including simple product questions. ElastiCache can improve response times for repeated queries. However, using Sonnet for all traffic is not cost-effective because 80% of the queries are simple product questions that a more efficient model could handle. This solution does not optimize resource usage based on query complexity.

B
Use Amazon Bedrock intelligent prompt routing. Use Anthropic Claude Haiku as the primary model. Use Claude Sonnet as the fallback model. Configure the routing policy to send simple queries to Claude Haiku and to send complex queries to Claude Sonnet.

Correct. Amazon Bedrock intelligent prompt routing provides dynamic model selection based on query characteristics. Using Claude Haiku for simple product questions provides faster, more cost-effective processing. Routing complex reasoning tasks to Claude Sonnet ensures high-quality responses for sophisticated queries. This solution optimizes both cost and performance by matching query complexity to model capabilities.

Implementing semantic similarity scoring and managing cached responses requires additional operational overhead. This solution does not effectively address the different complexity levels of queries. This solution might not maintain response quality for complex reasoning tasks.
