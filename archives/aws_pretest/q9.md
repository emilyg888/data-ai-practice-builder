Question
A global academic publishing company is developing a comprehensive research system that will store millions of scientific papers in Amazon S3. The system will use FMs in Amazon Bedrock to generate insights, recommend related papers, and provide natural language querying. The system must do the following:

Record when authors publish, submit, and update papers.
Store complete authorship information including name and contact details.
Classify papers across multiple scientific disciplines, sub-disciplines, and methodologies.
Provide search and filter capabilities by using complex criteria that combines metadata elements.
Provide FMs with rich contextual information about each paper to improve response quality.
Which metadata framework design will meet these requirements with the FASTEST query response?

Correct answer: D

A
Store timestamps as S3 user-defined metadata. Store authorship details and classifications in Amazon DynamoDB. Use S3 object keys as partition keys. Use S3 object tags for disciplines. Deploy Amazon OpenSearch Service for indexing and search.

Incorrect. Storing timestamps as S3 user-defined metadata has limitations for complex querying. Using S3 object tags only for high-level disciplines does not support the granular classification that you need across multiple scientific disciplines. DynamoDB provides fast access to authorship details. However, this design lacks the semantic search capabilities that you need for effective FM integration.

B
Store timestamps as S3 system-defined metadata. Store authorship details and classifications in an Amazon RDS for PostgreSQL database that links to S3 object keys. Use Amazon Kendra with custom document attributes for search.

Incorrect. RDS for PostgreSQL can store complex metadata relationships. However, using a separate relational database poses potential synchronization challenges. Amazon Kendra document attributes are useful for search. However, the document attributes do not provide the optimized vector-based capabilities that you need for FM interactions.

C
Store all metadata in Amazon DynamoDB. Use composite keys to enable various access patterns. Store the papers in Amazon S3 with minimal metadata. Set up S3 Event Notifications to maintain synchronization between services. Implement Amazon SageMaker Feature Store to prepare metadata features for FM interactions.

Incorrect. DynamoDB can support various access patterns through composite keys. However, when you store all metadata separately from the documents, maintaining consistency is more challenging. Feature Store is designed for ML feature management and is not optimized for metadata preparation.

D
Store timestamps as S3 system-defined metadata. Store authorship details as S3 user-defined metadata. Create a hierarchical S3 object tag structure for scientific classifications. Integrate with Amazon OpenSearch Service enhanced with document vectors from Amazon Bedrock for semantic search capabilities.

Correct. You can use S3 system-defined metadata for timestamps to provide reliable tracking. User-defined metadata efficiently stores authorship information. The hierarchical S3 object tags structure provides multi-level scientific classification. OpenSearch Service enhanced with document vectors from Amazon Bedrock provides powerful semantic search capabilities. This design provides both efficient metadata management and the rich contextual information that you need for FM interactions. This design provides the fastest query response to support advanced filtering and semantic search across millions of documents.
