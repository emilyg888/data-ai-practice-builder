Question
A startup company is building a general-purpose generative AI (GenAI) assistant to handle customer questions for a variety of use cases. The company builds the GenAI assistant by using Amazon Bedrock FMs.

The company wants to implement a query-routing mechanism based on the complexity of the query. Simple queries should route to a small Meta Llama model. Complex queries should route to a large Anthropic Claude model. For example, complex queries require generating creative responses or in-depth explanations. The solution must be scalable and able to maintain low-latency responses.

Which solution will meet these requirements?

Correct answer: B

A
Configure an Amazon Bedrock intelligent prompt router for the Llama and Claude models. Set a fallback model with a reliable baseline. Test the router by using different response quality differences between the models. Use an AWS Lambda function to invoke the configured Amazon Bedrock router by using the query.

Incorrect. You can use Amazon Bedrock intelligent prompt routing to route requests to different models based on the predicted response quality of each model. The intelligent prompt routing feature supports routing only between models from the same model families. Therefore, you cannot use this feature to route between Llama and Claude models.

Learn more about Amazon Bedrock intelligent prompt routing.

B
Use an AWS Lambda function to invoke a small Amazon Bedrock model by using the query. In the system prompt, instruct the model to determine if the query is complex and reply only if the query is too complex. When the model response returns to the Lambda function, inspect the response. If the response is too complex, invoke a larger model by using the same query.

Correct. Model cascading through sequential model invocation provides an efficient way to handle query complexity. First, you can use a small model to determine complexity and then invoke the larger model only when necessary. This solution optimizes both cost and performance. The smaller model quickly handles simple queries. Complex queries get the full capabilities of a larger model.

Learn more about Amazon Bedrock pricing.

C
Create an Amazon Bedrock knowledge base to store query patterns and complexity indicators. Configure an AWS Lambda function to first check the knowledge base to determine query complexity and then route to the appropriate model based on the complexity assessment.

Incorrect. You can use Amazon Bedrock Knowledge Bases to retrieve relevant information from your data sources to augment model prompts. Knowledge bases cannot analyze query complexity or route between different models. This solution would not efficiently determine query complexity.

Learn more about Knowledge Bases.

D
Create an AWS Step Functions workflow that first invokes an AWS Lambda function. Configure the function to analyze query length, keyword presence, and structural complexity by using regex patterns. Configure the workflow to route the query to either the small Llama model or the large Claude model based on predefined complexity thresholds.

Incorrect. Using Step Functions with regex patterns for complexity analysis is too simplistic to accurately determine query complexity. Regex patterns are text-matching patterns that you can use to search, match, or manipulate strings of text based on specific rules. This solution would miss semantic complexity that cannot be detected through simple pattern matching. This solution would require ongoing maintenance of regex patterns.

Learn more about Step Functions.
