OpenSearch Service with the k-NN plugin can handle distributed similarity search across billions of product catalog vectors with custom relevance scoring. OpenSearch Service provides a distributed architecture that can scale to billions of vectors across multiple shards. OpenSearch Service is unique in providing custom plugins to fine-tune search relevance compared to the other options.

Aurora PostgreSQL with pgvector is the only option that can combine metadata with vector search while maintaining strong consistency for financial records. Aurora PostgreSQL with pgvector provides atomicity, consistency, isolation, and durability (ACID) compliance. This configuration provides complex SQL querying capabilities and vector similarity search. This configuration is suitable for applications that require both precise metadata filtering and reliable transaction handling.

Neptune with vector search is the most suitable option for graph-based vector search applications that require relationship analysis between connected data points. Neptune combines graph database capabilities with vector search. Therefore, Neptune provides semantic similarity search that traverses relationships between entities. You can use Neptune when understanding connections is crucial. For example, Neptune is the most suitable option for research paper citation networks.

DynamoDB with vector support is a NoSQL database service that provides vector storage capabilities. This configuration provides storage and retrieval of vector embeddings with other item attributes. DynamoDB can store vectors and perform basic similarity search. However, DynamoDB does not support custom relevance scoring or distributed similarity search at a billion-vector scale. DynamoDB does not provide the strong consistency and complex metadata filtering capabilities that you need for financial record keeping. Additionally, DynamoDB does not provide automated content processing and built-in FM optimization. DynamoDB vector support is most suitable for less complex vector storage use cases where NoSQL flexibility is the primary requirement.
