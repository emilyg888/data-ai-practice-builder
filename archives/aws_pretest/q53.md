Question
A company is developing a customer support AI assistant by using Amazon Bedrock FMs. The AI assistant needs to process complex customer inquiries that require detailed analysis and multiple steps to resolve. Currently, users wait for the complete analysis before seeing any response. The delay negatively impacts user satisfaction. The company wants to optimize the user experience by showing progressive responses while performing the analysis.

Which solution will meet these requirements with the LEAST development effort?

Correct answer: A

A
Create an Amazon API Gateway WebSocket API with AWS Lambda integration. Use the Amazon Bedrock InvokeModelWithResponseStream API to stream tokens to connected clients. Configure a Lambda function to handle WebSocket connections and message delivery.

Correct. API Gateway WebSocket APIs provide managed, bidirectional communication channels that are suitable to stream data. The InvokeModelWithResponseStream API provides token-by-token streaming of model responses. Lambda functions can efficiently process the streams and forward tokens through WebSocket connections to clients. This solution provides real-time streaming with minimal latency and development effort. This solution maintains scalable, persistent connections.

B
Create an AWS AppSync real-time API with AWS Lambda resolvers. Configure a GraphQL schema to stream responses. Use the Amazon Bedrock InvokeModel API and implement subscription resolvers for client updates.

Incorrect. AWS AppSync is a managed GraphQL service that supports real-time updates through subscriptions. However, AWS AppSync requires more development effort for schema design and resolver implementation. Additionally, managing GraphQL types, mutations, and subscriptions adds development effort. The InvokeModel API returns only after the model finishes. Therefore, this solution does not provide incremental tokens to forward to clients. The AWS AppSync subscription would publish a single final message, not progressive updates while the analysis runs.

C
Deploy a REST API in Amazon API Gateway. Configure parallel synchronous InvokeModel API calls. Store responses in an Amazon DynamoDB table. Implement client-side polling to check for updates in DynamoDB Streams.

Incorrect. API Gateway REST APIs do not support built-in streaming capabilities. Using DynamoDB to store intermediate results and implementing client-side polling with DynamoDB Streams creates additional latency and development effort. This solution increases API calls and database operations. This solution does not improve user experience because of polling delays.

D
Implement HTTP APIs with AWS Lambda integration. Configure batch processing of responses by using AWS Step Functions. Store partial results in an Amazon DynamoDB table for client retrieval by using scheduled polling.

Incorrect. HTTP APIs with Step Functions batch processing requires additional development effort. Additionally, this solution does not provide real-time updates. Storing partial results in DynamoDB and implementing scheduled polling creates latency through repeated API calls. This solution does not meet the requirement for progressive responses. This solution requires additional infrastructure management.
