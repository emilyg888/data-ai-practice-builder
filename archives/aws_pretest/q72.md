Question
A large social media company runs multiple RAG pipelines across different applications. Each pipeline uses an FM embedding endpoint deployed on an Amazon SageMaker AI real-time endpoint. A GenAI developer uses the endpoint to generate embeddings. The GenAI developer stores the embeddings in multiple vector databases. The production applications use the vector databases to drive document retrieval for downstream generation and to provide users with content.

Recently, multiple users report that the response relevance has been poor. New writing styles are appearing more frequently. The GenAI developer wants to determine if the input drift is degrading embedding quality. The GenAI developer must prepare the model for re-training without disrupting production traffic.

Which combination of steps will meet these requirements? (Select TWO.)

Correct answer: C + D

A
Create a new SageMaker AI endpoint with Data Capture enabled. Shift all production traffic to the new endpoint. Delete the previous endpoint. Parse captured data in SageMaker Model Monitor to investigate.

Incorrect. Data Capture is a SageMaker AI feature that you can use to log actual production interactions for real-time or batch-transform endpoints. Data Capture reliably logs both requests and responses to Amazon S3. Data Capture ensures that you can use the responses for further drift detection and analysis. However, this step does not meet the requirement to avoid disrupting production traffic. Re-creating the endpoint will disrupt traffic.

Learn more about how to monitor data quality.

B
Schedule SageMaker Model Monitor jobs by using SageMaker Clarify to improve visibility into potential bias. Store the final violation reports in Amazon S3.

Incorrect. You can use Clarify to detect and mitigate bias in models. Clarify provides model explainability. Clarify integrates with Model Monitor to track model bias and feature attribution drift. This step improves visibility into potential bias that might emerge over time. However, this step does not address semantic embedding drift in production inputs.

Learn more about Clarify.

C
Schedule SageMaker Model Monitor with a custom Amazon ECR image. Compute all the drift metrics between the endpoint captured data and the baseline training dataset used by the model. Store the final violation reports in Amazon S3.

Correct. Model Monitor is a fully managed service that provides continuous monitoring of production ML models. Model Monitor runs scheduled jobs by using custom images. This approach can compute embedding-level drift metrics by comparing captured inference data (the data capture logs) against a baseline dataset. Storing the final violation reports in Amazon S3 ensures that you have an auditable record of drift events.

Learn more about Model Monitor.

Learn more about how to detect natural language processing data drift by using Model Monitor.

D
Create a new SageMaker AI endpoint configuration based on the production variant with Data Capture enabled. Use the UpdateEndpoint API to shift endpoint traffic to the new endpoint with the updated configuration. Parse captured data in SageMaker Model Monitor to investigate.

Correct. Data Capture is a SageMaker AI feature that you can use to log actual production interactions on real-time or batch-transform endpoints. Data Capture reliably logs requests and responses to Amazon S3. Data Capture ensures that you can use responses for further drift detection and analysis. The UpdateEndpoint API call shifts SageMaker AI endpoint traffic to the new instances with the updated endpoint configuration. Then, the call deletes the old instances by using the previous configuration. This step maintains availability and creates an intrinsic blue/green deployment.

Learn more about Data Capture.

Learn more about how to monitor data quality.

Learn more about UpdateEndpoint.

E
Change all RAG pipelines to use an Amazon Bedrock Titan Embeddings model endpoint. Enable model invocation logging. Select embedding as the data type to capture. Set up logs to publish to Amazon S3.

Incorrect. You can use the Amazon Bedrock invocation logging feature to collect the entire request data, responses, and any metadata associated with all calls performed to that endpoint. However, Titan Embeddings is not the FM embedding endpoint that the company owns. Additionally, switching all RAG pipelines to use Amazon Bedrock will cause some downtime.
