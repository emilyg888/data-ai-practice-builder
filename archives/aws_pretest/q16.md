Question
A company that provides help desk software uses Amazon Bedrock to automate customer support ticket triage. Following AWS best practices, the system uses a well-structured prompt template that includes defined categories, examples, and validation requirements. The architecture consists of the following elements:

Amazon API Gateway for ticket ingestion
An AWS Lambda function for ticket processing and model interaction
An Amazon Bedrock InvokeModel API for classification
Response validation before downstream processing
The company notices intermittent issues where some tickets receive unexpected classifications. The company needs to identify the root cause of these anomalies.

Which approach will meet these requirements?

Correct answer: C

A
Use Amazon CloudWatch Logs Insights to analyze Lambda function logs for error patterns in ticket processing and model responses.

Incorrect. CloudWatch Logs Insights is a query tool that you can use to search and analyze log data that is stored in CloudWatch Logs. You can use CloudWatch Logs Insights to analyze function-level errors and exceptions. However, CloudWatch Logs Insights would not provide detailed visibility into the specific model interactions that cause intermittent classification anomalies. To troubleshoot occasional unexpected classifications, direct inspection of model interactions would be more effective.

Learn more about CloudWatch Logs Insights.

B
Use AWS X-Ray traces to identify if there are timeout or throttling issues between the Lambda function and the Amazon Bedrock API calls.

Incorrect. X-Ray is a distributed tracing service that helps analyze and debug application performance and service interactions. X-Ray traces can help identify performance issues, latency, or API throttling problems in service interactions. However, the architecture already implements best practices and validation. Therefore, the root cause of the intermittent classification issues relates to specific model interactions, not service integration problems.

Learn more about X-Ray.

C
Enable Amazon Bedrock model invocation logging to inspect the raw prompts being sent and the responses received from the FM.

Correct. Model invocation logging provides detailed logs of model interactions, including prompt content and responses. You can use this approach for direct analysis of cases where unexpected classifications occur. This approach helps identify patterns or specific conditions that led to anomalies despite the well-structured prompts and validation. This approach provides the most direct insight into intermittent model behavior issues.

Learn more about model invocation logging.

D
Create a custom Amazon CloudWatch metric that tracks the distribution of classified categories. Set up an alarm for unexpected spikes in specific labels or null values.

Incorrect. CloudWatch metrics are data points that provide information about the performance of systems and applications. Alarms can monitor metrics and take actions. Monitoring classification distribution through CloudWatch metrics can help detect anomalies. However, this approach would identify only when issues occur, not why the issues occur. The system already includes response validation and follows best practices. Therefore, understanding the specific model interactions in anomalous cases would be more valuable for root cause analysis.

Learn more about CloudWatch custom metrics.
